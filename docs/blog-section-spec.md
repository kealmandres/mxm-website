## 1. URL structure

- The index: https://www.themxm.ai/future-observatory/blog/
- One page per article: https://www.themxm.ai/future-observatory/blog/<slug>, where the slug is lowercase, hyphenated and permanent.
- No query strings.
- The final URL on www.themxm.ai everywhere: canonicals, the sitemap, llms.txt and internal links. The canonical form of an article is exactly its URL above.

## 2. Page template

Static HTML, with all the article text in the raw HTML (no JavaScript needed to read it). In this order:

1. H1.
2. The direct answer, 20 to 80 words, as the first paragraph.
3. Question-led H2 sections.
4. FAQ.
5. Author byline: Marissa Kos.
6. A visible "Last updated" date.
7. Internal links.

## 3. Schema templates

Article, in the article's <head>:

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "<the H1>",
  "datePublished": "<YYYY-MM-DD>",
  "dateModified": "<YYYY-MM-DD, the real last change>",
  "author": {
    "@type": "Person",
    "name": "Marissa Kos",
    "url": "https://www.themxm.ai/blonde-bot-lair"
  },
  "publisher": {
    "@type": "Organization",
    "name": "The MaCHiNE MaiSON",
    "url": "https://www.themxm.ai/"
  },
  "image": "https://www.themxm.ai/assets/images/<hero image>",
  "mainEntityOfPage": {
    "@type": "WebPage",
    "@id": "https://www.themxm.ai/future-observatory/blog/<slug>"
  }
}
```

Person, for Marissa Kos:

```json
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Marissa Kos",
  "url": "https://www.themxm.ai/blonde-bot-lair",
  "sameAs": [
    "https://www.linkedin.com/in/marissa-kos-ai/"

```

FAQPage, built from the page's own FAQ block:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "<a question, word for word as on the page>",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "<its answer, word for word as on the page>"
      }
    }
  ]
}
```

In llms-full.txt, the article's full text under its own heading:

```text

<the article text>
```

## 6. Design-safe text placement guide

Where text can live without hurting the design, so the later website facelift inherits it:

- FAQ accordions carrying FAQPage schema.
- Collapsible transcripts under videos.
- Captions under images and video.
- Alt text.
- Schema in <head>.
- "Last updated" and the byline in the article meta line.

The direct answer and the main argument are always visible, never inside an accordion.

Never: text hidden from people but shown to crawlers. That is cloaking, and the audit reports it as blocking.
